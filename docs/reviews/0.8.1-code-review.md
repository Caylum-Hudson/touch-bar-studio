# Touch Bar Studio 0.8.1 code review

## Findings fixed

1. **High — unreadable workspace data could be replaced silently.** `StudioStore` now distinguishes a missing workspace from an unreadable or invalid one. The UI reports the load error and requires either importing a workspace or confirming replacement. The native save API also enforces that guard, archives the original unreadable bytes under a unique name, and leaves `workspace.previous.json` intact. Before replacing any existing file, the store preserves a valid current workspace as `workspace.previous.json`. Temporary-directory self-tests exercise invalid JSON, save refusal, explicit archival, and profile validation without touching the real workspace.
2. **High — widget callbacks and child processes outlived removed controls.** Audio listeners now use a stable main-queue registration/removal path and are removed on deallocation. Battery run-loop sources are invalidated and removed before their retained callback context is released. Repeating status timers use weak callbacks and invalidate on teardown; background scheduler callbacks no longer retain their widgets. Up Next also removes its EventKit observer and cancels its scheduler. The network widget now removes both notifications, closes its pipe, terminates its owned `netstat` child on teardown or EOF, parses complete lines, and bounds incomplete output to 16 KiB. A native lifecycle check repeats safe read-only widget create/release 20 times; it does not trigger widget actions, request calendar/weather access, or alter settings.
3. **Medium — local builds accumulated obsolete hashed web assets.** Packaging now stages the current Vite output in a sibling temporary directory, verifies the file manifest and SHA-256 content, then swaps it into the bundle with rollback. This both removes stale assets and preserves the old web app if the source build is absent or invalid. A temporary-directory regression test covers stale-asset removal and source-failure preservation.
4. **Medium — duplicate enabled profile bundle IDs had ambiguous selection.** Native workspace validation now rejects duplicate active app-profile identifiers before saving. Disabled duplicates remain permitted.
5. **Medium — the workspace recovery poller used stale import state.** A ref now keeps the long-lived two-second refresh callback aligned with the current import state, so polling after an import does not replace the recovery status with the “import a backup” warning.
6. **Low — malformed Auto-load preference data could abort React initialization.** Loading that local-storage preference now falls back to the default enabled state when saved JSON is corrupt.

## Areas reviewed

- Profile selection and Resolve page routing: native profile matching applies a full selected profile; Resolve detection only accepts a unique selected, recognized page checkbox in the focused standard window. Unknown, ambiguous, or unavailable Accessibility data falls back safely. Added profile validation covers duplicate enabled bundle IDs.
- Workspace import/save: JSON shape validation remains in the editor and native store. The new corrupted-workspace path preserves bytes and requires an explicit replacement decision.
- Photo workspace: metadata is read separately from thumbnail generation, thumbnails are downsampled through ImageIO, and grid images use browser lazy loading. Opening a photo workspace uses selected paths and leaves originals untouched. This review did not load or export user photos.
- Layout placement: existing tests cover native bounds, reserved Control Strip space, auto Dock sizing, precise-position preservation, no-fit handling, and explicit usable-region placement. No saved layout or six-layout setup was changed in this review.
- Runtime overlays: the existing private compact-overlay close suppression remains unchanged; native expansion is kept as previously verified on hardware.
- CPU/memory: no controlled before/after runtime comparison was made. One prior single-process baseline was 3.0% CPU and 108,400 KiB RSS, which is insufficient to support a performance claim. No CPU/RSS savings are claimed here.

## Validation

- 29 Node tests passed, including the new WebApp staging regression.
- Local-build source checks passed: Resolve page isolation/round-trip, reducer and import behavior, shortcut serialization, precise/free layout behavior, and all 56 palette entries.
- Vite production build passed: JS 367.25 kB (112.51 kB gzip), CSS 51.01 kB (10.57 kB gzip).
- Scoped ESLint completed with zero errors and three React hook warnings: two existing dependency/memoization warnings in `AppContext.jsx`, plus the existing `app` dependency warning in `StudioShell.jsx`. The newly introduced stale workspace-replacement dependency warning is resolved.
- Native Swift sources compiled and the 0.8.1 app bundle built successfully. Sandboxed self-test invocation exited during AppKit/LaunchServices setup; rerunning the registered app's tests in the normal desktop context passed. The 20-cycle widget lifecycle test passed independently and within the full native self-test. The palette/widget fixture check also passed (56 palette defaults; 51 retained controls decode; 5 intentionally export-only controls are filtered), including read-only local metric checks. Physical taps, keyboard delivery, external services, Automation grants, and private system toggles were not exercised.
- Initial installed bundle measurement before these changes: 23,752 KiB total, including 20,872 KiB in `Contents/Resources/WebApp`. Final 0.8.1 bundle: 5,740 KiB total, including 2,816 KiB in `Contents/Resources/WebApp`. The current WebApp and `dist` file manifests match (88 files); only two current files are under `WebApp/assets` and no stale hashed chunks remain. The installed bundle is 18,012 KiB smaller than the prior measured bundle, primarily from removing superseded web assets. `dist` occupied 3,092 KiB on disk. No CPU/RSS savings are claimed.
