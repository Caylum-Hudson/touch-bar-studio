# Touch Bar Studio 0.11.3 — Persistent Focus countdowns

Focus and break timers use saved finish times rather than living inside a particular Touch Bar view. Changing applications or rebuilding a bar keeps the countdown running. Time spent asleep counts toward the selected duration; an expired timer completes when Studio can run again.

Active timers also survive restarting Studio. Each saved widget retains its own timer, and completed timers are cleared before sending their notification to avoid repeating it after another rebuild. Tap to start or stop Focus; hold to start or stop a break, as before.

The Studio control library explains this behavior. Existing layouts and timer duration settings are preserved.

Validation: all 67 frontend tests, the native self-test, and the control self-test pass. The executable timer checks cover persisted deadline restoration, independent timer keys, completion while hidden, exactly-once delivery, multiple views, and weak view release. The production frontend matches the installed bundle, its signature verifies, and the saved workspace is unchanged. Physical sleep/wake and Touch Bar interaction still need a hardware check.
