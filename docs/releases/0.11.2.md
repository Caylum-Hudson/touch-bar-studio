# Touch Bar Studio 0.11.2 — Native Resolve Color Touch Bar

Touch Bar Studio can yield to DaVinci Resolve’s native Touch Bar when Resolve is foregrounded on its detected Color page. The preference defaults on and is saved with the workspace. The detected Resolve page takes priority over the manual Touch Bar page while native Color is enabled. Studio cancels active custom interactions when handing off, then restores its custom layout on Edit and other pages. The Studio editor identifies when native Color controls are active.

Resolve Color dial, numeric dial, and timeline-jog work is cancelled or blocked during the handoff. Learning or testing an HDR binding while native Color is active asks the user to switch back to the custom Color bar.

Restoring and saving a workspace now preserves the native identity of existing System Monitor controls. Duplicating a control or group assigns fresh identities to the copy and nested controls, avoiding collisions with live widget data.

## Verification and known issues

- With Accessibility access granted, turning the preference off survived a 3.5-second status poll; turning it on and selecting Apply & Save persisted `useResolveNativeColorPage: true`. A workspace without this preference defaulted on.
- After the stable-ID fix, relaunching and applying the workspace left all profile data exactly equal to the pre-fix baseline, including IDs and positions.
- The Studio UI reported “Active on Touch Bar · DaVinci Resolve · Native Color page” and displayed the native Color controls banner.
- All 66 frontend tests, both native self-tests, strict code-signature verification, and comparison of all 89 staged web assets passed.
- **Physical Color-to-Edit switching is user-verified.** On 2026-10-27 (Pacific/Auckland), the user confirmed that Resolve’s native Color Touch Bar and restoration of the saved Studio bar on Edit both switch correctly. This confirms those page-switch behaviors; other hardware gestures and HDR learning remain unverified.
