# Resolve page layouts

Version **0.6.0** adds independent page layouts to DaVinci Resolve app profiles. The opt-in setup creates a Resolve profile as a copy of Default, with the existing 12 timeline controls on Edit and eight manual shortcuts on Color. It preserves other profiles and any layouts already configured. The eight Resolve pages appear in the selectors; a page without its own layout uses the Resolve profile fallback until the user explicitly creates a copy.

When Resolve is frontmost, the native app reads the selected page from direct Accessibility controls in its standard window. Studio and the Touch Bar include a manual page choice as a fallback. Page detection requires Accessibility access and uses the profile fallback when the selected page cannot be read reliably. Studio's editing selector chooses the layout being edited; it does not change the page inside Resolve.

KeyPress shortcuts can now include simultaneous Command, Option, Shift, and Control modifiers. Existing unmodified and legacy key actions retain their previous behavior. The Color starter shortcuts were checked against Blackmagic's Resolve manual.

Browser QA confirmed that Edit and Color receive separate templates, edits remain page-specific, shortcut modifiers can be edited, and saved layouts return after reload. The installed 0.6.0 app launched, the Resolve profile was saved with its Edit and Color layouts, and the existing Default profile and settings were preserved. A read-only comparison with `workspace.previous.json` confirmed that Default and settings match; Resolve has 12 Edit controls and eight Color shortcuts. macOS Accessibility reports Granted for the final installed binary. On that binary, Auto followed Edit → Color → Fairlight → Edit, with the Resolve profile fallback used for Fairlight. Manual Color selection followed by returning to Auto was verified on the immediately preceding 0.6.0 binary.

The final native build is installed and passed strict code-signature verification and `--self-test`. A transient internal marker prevents user-created first groups titled Auto or Manual from being treated as the generated page picker; regression checks cover both title collisions and preservation of saved positions. The earlier 0.6.0 binary, sampled with Resolve inactive and Studio open, measured 2.47% mean CPU and 68.95 MiB mean RSS over 20 seconds. On the final binary, with Auto mode enabled during live testing and Resolve foreground verified at sample setup, 20 seconds measured 1.60% mean CPU and 103.87 MiB mean RSS; foreground state was not continuously logged. Both samples cover only the TouchBarStudio main process and exclude WebKit/helper processes; they are separate snapshots from different binaries and states, not an A/B estimate of detector overhead, total UI use, or battery use. The earlier active sample overlapped page switching and is superseded. Physical Touch Bar pixels, taps, and shortcut delivery have not been tested. This is a source version update, not a published GitHub release.
