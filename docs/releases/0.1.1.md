## Fix: repeated permission requests

Version **0.1.1** removes the unconditional macOS permission request at startup. Access is checked silently. When permission is missing, the app shows an **Open permission settings** button, and keyboard/media events are blocked instead of attempting input.

![Quiet permission notice](https://raw.githubusercontent.com/Caylum-Hudson/touch-bar-studio/v0.1.1/docs/screenshots/permission-notice.png)

### Why a previous grant may not work

Local builds are ad-hoc signed. Their code identity changes when the app is rebuilt, so an old permission entry can be On without authorizing the new binary. This patch stops automatic requests; it does not bypass permission or grant it automatically.

For keyboard controls, open Privacy & Security → Device Control and Data Access (Accessibility on earlier macOS). If the existing Touch Bar Studio entry is stale, remove it and add the updated app, then reopen the app. The editor, launcher and photo browser work without this grant.

Builds can now use an existing reusable certificate through `STUDIO_SIGNING_IDENTITY`. No certificate or system trust settings are created automatically. Ad-hoc updates can still need a fresh manual grant.

### Verification

Production/native build and existing tests pass. Added denied/granted permission-gate tests without sending input events. Two native launches showed no automatic permission dialog; the explicit settings button opened the correct pane. Physical Touch Bar behavior remains unverified, so this is still a prerelease.
