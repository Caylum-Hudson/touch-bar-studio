# Touch Bar Studio 0.9.2 — Compact Date and System Monitor widths

Studio now estimates Date and System Monitor widths more tightly. Abbreviated weekday and month tokens remain abbreviated during sizing, the Date preview matches the native text-only control, and System Monitor keeps room for its worst-case selected values without extra padding. Properties adds a Fit to content action for these controls; existing saved widths are preserved until selected. No native width override is applied beyond AppKit's measured intrinsic `fittingSize`.

## Verification

- All 43 frontend tests pass. The full production build and native self-tests pass.
- The native intrinsic-width self-test measures Date at 53 pt for `Sep 30` and 88 pt for `Wed Sep 30`. The four-reading System Monitor measures 237 pt: 195.3 pt of text, a 20 pt icon, and 21.7 pt of AppKit cell/gap. Native intrinsic sizing remains unchanged.
- At a 685 pt custom-area width (685/1085 preview scale), Fit to content recommends 102 logical units for `MMM d` and 376 for the four-reading monitor; the explicit long weekday/month format `EEE MMM d` recommends 140. These fit recommendations preserve the current metric selection and other controls' positions.
- Studio preview uses 15px regular text and a 20px System Monitor icon for native-size content inside the measured preview width.
- Final app bundle is version 0.9.2; staged JavaScript and CSS hashes match the production build. All four System Monitor values fit in the installed preview, and the Date and monitor text match native sizing.
- Installed QA confirmed the saved layout changed only the Date width (64 → 102) and System Monitor width (381 → 376); positions, metric selection, and other controls were preserved. Accessibility is granted with no warning. [Installed screenshot](../screenshots/compact-widgets-installed-0.9.2.png).
