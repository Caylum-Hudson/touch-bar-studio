# System metric controls

Source version **0.7.0** adds RAM usage, GPU usage, and motherboard-temperature entries to the Studio library.

RAM is a native host-statistics estimate: non-purgeable internal pages plus wired and compressed pages, divided by physical memory. Its native detail text includes used/total bytes and the formula. GPU usage is read from the system-wide IOAccelerator device-utilization property; the busiest device is selected if more than one is present. A single serial sampler reads only the requested metric every two seconds while RAM or GPU widgets exist, reusing one cached Mach host send right for RAM reads. The unavailable board item starts no sampler.

Motherboard temperature is explicitly unavailable on this build. The local Apple Silicon PMU sensor names found during a bounded read-only check identify PMU/die/device and battery sensors, but no board sensor. CPU, GPU, PMU, and package temperatures are not relabelled as motherboard temperature.

The editor preview uses static illustrative labels and does not read live values. Browser fixture QA confirmed the worst-case labels fit at 1280×720 with the Properties sidebar open, and confirmed library search/add/remove behavior. Installed-app UI QA confirmed the original three-control Default and temporarily added/positioned RAM and GPU without saving those additions; Board remained unavailable. The installed 0.7.0 build passed strict signature verification and the native widget self-test, which observed live RAM and GPU values while keeping Board unavailable.
