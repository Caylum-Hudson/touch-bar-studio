# 0.8.1 — Workspace safety and runtime cleanup

Touch Bar Studio 0.8.1 protects saved layouts when the workspace file is unreadable, makes workspace replacement explicit, and preserves both the original unreadable bytes and any prior valid backup. Native validation also rejects duplicate enabled app-profile bundle IDs.

Local packaging now verifies the complete web build in a temporary directory before replacing the bundle’s WebApp folder, removes superseded hashed assets, and restores the prior folder if the replacement fails. Widget teardown now releases audio listeners, battery callback context, repeating timers, background scheduler observers, and the network monitor process. The editor safely defaults malformed Auto-load preferences and keeps its recovery status current after importing a workspace.

The current installed build passed the native self-tests, a 20-cycle lifecycle check, the 56-entry palette audit, widget read-only checks, 29 frontend tests, source/catalog checks, and strict signature verification. Installed UI review confirmed the existing six-control layout, no workspace warning, and Accessibility granted. No workspace bytes were compared with a prebuild hash, and the visible corrupted-workspace import/confirmation flow was not tested end to end; temporary-directory native tests cover the preservation and save guards. Physical Touch Bar actions and external-service behavior remain unverified.

The app bundle measures 5,740 KiB, compared with 23,752 KiB before stale web-asset cleanup. This is a package-size measurement only; no CPU or memory improvement is claimed. See the [code review](../reviews/0.8.1-code-review.md) and [verification record](../../VERIFICATION.md).
