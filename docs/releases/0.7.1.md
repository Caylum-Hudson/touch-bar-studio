# 0.7.1 — CPU temperature

Version **0.7.1** replaces the unavailable motherboard-temperature palette item with **CPU Temperature**. Existing saved motherboard-temperature entries remain decodable and show **Board —**, but the item is no longer offered for new layouts.

The native widget reads model-exposed AppleSMC `Tp`/`Te` float keys through unprivileged, read-only IOKit calls. It enumerates names and types once, retains that inventory across profile changes, and samples only while a CPU-temperature widget is active using the shared two-second sampler. It shows the hottest plausible value as `N°C`; this is the hottest available CPU sensor, not a package or die average. Macs that do not expose usable CPU keys show **—**. Apple does not publish a stable SMC key map; the CPU sensor-family interpretation follows the community-maintained [Stats M1 sensor table](https://github.com/exelban/stats/blob/master/Modules/Sensors/values.swift), so coverage can vary by chip generation.

A local read-only probe on MacBookPro17,1 found 36 `Tp`/`Te` float keys, with sampled values from 35.60°C to 59.91°C. The staged native diagnostic returned `CPU 63°C`, RAM 66%, and GPU 5%; it measured the one-time key inventory at 13.05 ms and a cached-key sample at 10.62 ms across 36 sensors. The editor preview uses a static worst-case label and does not read live temperatures.

Frontend checks, five width tests, lint, Vite production build, Swift compilation, installed native self-tests, and installed UI review passed. The installed widget check read RAM 65%, GPU 18%, and CPU 63°C; a separate diagnostic read CPU 74°C and measured 11.25 ms for key inventory and 9.83 ms for a cached-key sample. Strict signature and 0.7.1 version checks passed. The live palette exposes CPU Temperature and no motherboard card; the saved Default and Resolve layouts were preserved. Isolated browser QA confirmed CPU add/remove and CPU/RAM/GPU worst-case label fit at 1280×720. The [fixture screenshot](../screenshots/cpu-temperature-0.7.1.png) is an editor preview, not a Touch Bar capture. CPU readings need no new permission. Physical Touch Bar pixels and taps are not verified.

Final compact controls use distinct CPU, memory-chip, display, and thermometer icons with prefixless percentage/temperature labels. CPU usage rounds to a whole percentage; full metric names remain in accessibility labels and tooltips. The rebuilt app passes native widget and live-width checks, all five sizing tests, strict signature verification, and the 0.7.1 version check. Final samples were RAM 62%, GPU 14%, and CPU temperature 54°C; a separate diagnostic read 55°C with 12.36 ms key inventory and 10.75 ms cached-key sampling. The latest saved Default has six controls including CPU Temperature; Resolve retains 12 Edit and eight Color controls.

The app reapplies the current configured close-box policy on the main loop after modal presentation. This addresses the intermittent unconfigured leading close control; physical confirmation remains pending. Final installed-app UI review passes: the latest six-control Default shows distinct CPU chip, RAM module, GPU monitor, and thermometer icons with fitting illustrative `100%` and `130°C` labels. Accessibility was refreshed for the exact rebuilt bundle and reports granted. See the [installed editor screenshot](../screenshots/compact-metrics-installed-0.7.1.png); it records the editor UI, not physical Touch Bar pixels. Version 0.7.1 remains unpublished.
