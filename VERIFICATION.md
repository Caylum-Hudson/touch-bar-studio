## 0.7.0 — System metric controls (installed build verified)

- Added RAM, GPU, and motherboard-temperature controls to the palette and native item decoder. The editor preview uses static illustrative labels; it does not read or claim live system values.
- RAM comes from `host_statistics64`/`vm_statistics64_data_t`. The displayed estimate is `(internal_page_count − purgeable_count + wire_count + compressor_page_count) × vm_page_size`, divided by `ProcessInfo.physicalMemory` and rounded to a whole percent. Native detail text gives used/total bytes and explicitly says this formula is not Activity Monitor-equivalent. Apple documents the VM counters [here](https://developer.apple.com/documentation/kernel/vm_statistics64_data_t).
- GPU reads the `Device Utilization %` counter from local IOAccelerator registry properties. If multiple devices appear, the highest value is used rather than summing percentages. A missing or out-of-range counter produces **GPU —**. Apple’s public GPU counter-statistics workflow is scoped to Xcode profiling [here](https://developer.apple.com/documentation/xcode/analyzing-apple-gpu-performance-using-counter-statistics); the system-wide runtime counter used here is an IOKit observation and is not a public API guarantee.
- A bounded read-only local sensor-name check on this Apple M1 MacBookPro17,1 found AppleARMPMUTempSensor products `PMU tcal`, `PMU tdev1`–`tdev8`, `PMU tdie1`–`tdie8` (with model-specific gaps), `PMU TP3w`, `PMU2` tcal/tdev/tdie entries, and gas-gauge battery entries. None identifies a motherboard or logic-board sensor, so this build’s board-temperature item always displays **Board —** with an explanation; it does not substitute CPU, GPU, PMU, or package readings. Apple Silicon sensor integrations in [Chromium’s M1 sensor reader](https://chromium.googlesource.com/chromium/src/+/refs/tags/123.0.6285.0/components/power_metrics/m1_sensors_mac.mm) identify performance- and efficiency-core sensors, not a board temperature. Apple’s public `ProcessInfo.thermalState` is a qualitative thermal condition, not degrees Celsius [per its API documentation](https://developer.apple.com/documentation/foundation/processinfo/thermalstate-swift.property).
- A single serial sampler coalesces reads to a two-second cadence while RAM/GPU widgets exist, queries only the requested metric, and stops when the last RAM/GPU widget is removed. It reuses one cached Mach host send right for RAM reads rather than requesting another on every sample. The unavailable board item starts no sampler. It runs without shell commands, helper installs, privileged access, or added permissions.
- Browser fixture QA passed at 1280×720 with the Properties sidebar open: worst-case RAM/GPU labels and the unavailable Board label fit without ellipsis. RAM and GPU were searched, added, and removed from the library; Board displayed as unavailable and could not be added. The preview labels are static; live metric values were verified separately by native self-test and diagnostic.

- Read-only Objective-C runtime inspection on this Mac found `NSSystemModalTouchBarOverlay` with `_showsCloseWhenInactive` at byte offset 65. Disassembly of `showTouchBar:placement:systemTrayIdentifier:` assigns that Boolean to `(placement == 0)`. The no-placement `NSTouchBar.presentSystemModalTouchBar:systemTrayItemIdentifier:` wrapper explicitly passes placement 0. Placement 1 selects the full-bar presentation already used when Keep Control Strip is off. The wrapper validates only placements 0 and 1. This directly connects the native compact Control Strip mode to its inactive-app close control; repeated close-policy calls cannot change that presentation flag. No separate inactive-close setting was found in the runtime method inventory or SDK DFR exports. The normal presenter therefore retains this system-managed × while preserving the native Control Strip; the scoped subclass candidate below avoids that presenter’s close-update implementation. This is evidence from this macOS build, not a guarantee for all OS versions. No system patching, swizzling, or ivar writes were used.
